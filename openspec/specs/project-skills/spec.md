# project-skills Specification

## Purpose
Keeps the agent skills that belong to this project in a visible, versioned folder of the repository, and makes Claude Code load them from there.

## Requirements

### Requirement: Skills folder
Each project skill SHALL be a folder `skills/<name>/` at the repository root holding a `SKILL.md` whose frontmatter `name` equals the folder name and which has a `description`. A skill MAY hold other files that its `SKILL.md` refers to.

#### Scenario: Skill layout
- **WHEN** the repository is checked out
- **THEN** `skills/ingest/SKILL.md` exists with `name: ingest` and a description in its frontmatter

### Requirement: Skills loaded by Claude Code
Each project skill SHALL be linked from `.claude/skills/<name>` by a committed relative symbolic link to `../../skills/<name>`, so that Claude Code started in the repository offers it. Skills generated by other tools in `.claude/skills/` SHALL be left as they are.

#### Scenario: Skill available
- **WHEN** Claude Code is started in a fresh clone of the repository
- **THEN** the `ingest` skill is listed and can be invoked as `/ingest`

#### Scenario: Generated skills untouched
- **WHEN** the links are added
- **THEN** the existing `openspec-*` folders in `.claude/skills/` are unchanged

### Requirement: Link check
The test suite SHALL fail when a folder in `skills/` has no `SKILL.md`, its `name` does not match the folder, or `.claude/skills/<name>` is missing or does not resolve to that folder, and the failure SHALL name the skill.

#### Scenario: Missing link
- **GIVEN** a folder `skills/new-one/` with a valid `SKILL.md` and no link in `.claude/skills/`
- **WHEN** the tests run
- **THEN** a test fails naming `new-one`

#### Scenario: All linked
- **WHEN** every skill has its link
- **THEN** the check passes
